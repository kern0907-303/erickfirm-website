# NAS 月信產文管線（草案實作）

## 狀態

- 只產生待審草稿；沒有寄信、寫入名單、資料庫或 Resend 的程式介面。
- number profile 0 的候選定義仍待 Erick 最終確認；即使輸入候選 profile，前置攔截也會 blocked。relation rules v1 目前未定義 0。
- `monthly_questions` 舊版曾定案為四段固定順序；Erick 正在更新素材，收到新版前暫停月信內容定稿與真實產文器接線。
- 測試裡的 profile、題目與產文結果均為合成資料，不是正式素材。

## 資料邊界

`buildMonthlyNarrativePacket` 接收已計算的陽曆主命數、陰曆主命數、流月、profile catalog、`relation_rules.json` 與 `/api/nas/flow-window` 的日期區間。它只挑出 profile 的 `theme`、`strength`、`watch` 欄位；不接受或傳遞生日、姓名、Email。

四段題目依序為「想成為的樣子 × 流月」、「實際運作方式 × 流月」、「兩者落差 × 流月」及「本期適合／不適合硬推的事」。後置檢查逐段驗證當期字樣、流月 profile、指定的陽曆／陰曆 profile 與交互用語；靜態重述特質會 blocked。

日期、數值、關係規則與 profile 都是確定性資料。LLM 只輸出 `opening`、四段 `text`、`firstStep`、`nextCyclePreview` 等文字。日期與版型留在程式端的 `deterministicEnvelope`；未接任何 HTML renderer 或寄送 adapter。

## 攔截點

1. **前置檢查**：檢查數值範圍、profile 是否存在及 profile 對應數值、關係規則、流月日期連續性，以及四段問題是否為核可狀態且順序正確。任何一項失敗都不呼叫產文器。
2. **JSON 檢查**：產文器必須回傳純 JSON 字串；解析失敗、欄位多缺、段落順序錯誤均 blocked。
3. **內容檢查**：檢查禁用詞、型別名稱、感情數、數字衝突、開場長度及陽曆／陰曆／本期流月三個開場錨點；四段各自驗證 profile × 本期流月的交互錨點與題目要求。任一失敗不回傳可審草稿。
4. **來源紅線檢查**：提示詞只列適用的 `report_system.md` 條目。測試會確認每條提示詞紅線都是原檔精確片段；NAS 補充規則另以 Erick 已核可的清單明確列出，不冒稱來自原檔。

## 乾跑

```sh
npm run test:nas-monthly-pipeline
```

此測試只注入 mock 產文器，不連接模型服務、Supabase、n8n 或 Resend。
