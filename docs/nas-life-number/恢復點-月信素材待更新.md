# NAS 月信恢復點

更新日期：2026-10-26

## 暫停原因

- Erick 正在更新 `monthly_questions` 素材。收到新版以前，現有四段題目只代表舊版定案，月信內容不可視為最終版，也不要接真實產文器或發布流程。
- 主命數 `0` 的 profile 仍待 Erick 最終確認。先前口述草案「時機／辨識時機與留出空間／等不到對的時機就一直不動」尚未核可；`relation_rules.json` v1 也只定義 1–9，補 0 時要一併處理。

## 工程已完成

- `src/lib/nasMonthly/` 已有月信草稿管線：計算欄位與文案素材分離，前置檢查、JSON 解析、數值一致性、紅線、opening 個人化錨點，以及四段逐段「profile × 本期流月」攔截都已實作。
- 目前只有 mock 產文器與合成資料乾跑；未接真實 LLM、n8n、Supabase 或 Resend，未建立真實名單，也未寄信。
- 上述工程曾以 `npm run test:nas-monthly-pipeline` 驗收 11/11 通過；新素材進來後仍需更新案例並重跑驗收。

## 恢復順序

1. 取得 Erick 更新後的 `monthly_questions` 正式素材，替換目前程式與提示詞內的舊版問題；保留每段必須與本期流月互動的逐段攔截。
2. 取得數字 0 的正式 profile，並確認 `relation_rules.json` 對 0 的正式處理方式。
3. 更新測試資料與預期結果，重跑月信管線驗收；缺 profile、缺題目、數值衝突、禁用詞、JSON 解析失敗與逐段流月交互不足都必須保持 fail-closed。
4. 上述素材與攔截驗收完成後，下一步才是接真實 LLM 產文器；寄送與發布流程仍需另行授權及驗收。
